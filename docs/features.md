- [o] S1 — P1: Build, test and release this sidecar as its own repository. Moved on 2026-10-02 from the soksak core repository (checklist item R1-5-2 there), whose history holds the earlier changes. `make test`, `make build` and `make release` pass on macOS arm64.
- [o] S2 — P1: Open a surface again after its closed notice on the same persistent connection. Found on 2026-10-02 by the core window check `library windows create and open projects in place`: a project whose terminal was shown in a window that then closed could not be shown in a new window, because the terminal open was answered with `stale attachment` and the host waited for a terminal image that never came. The closed notice removed the registry entry but left the surface's sender and attachment epoch in the connection, so the next open compared the old epoch with a registry that no longer had the entry. Done on 2026-10-02: a successful close also removes them. Red: `a_surface_reopened_after_its_closed_notice_is_not_a_stale_attachment` received two `stale attachment` replies; Green: the test and `make test` pass on macOS arm64.
- [o] S3 — P1: Release version 0.0.2 for soksak core 0.0.2. Done on 2026-10-02: `vt-core` and `vt-alacritty` declare 0.0.2, which carries S2; `make test` passes on macOS arm64 (274 tests).
- [o] S4 — P1: Keep the output above a prompt that ends its own line when the terminal resizes. Found on 2026-10-02 by the core window check `a resize redraws a wrapped zsh input line without rows of the previous width` (core G1.4-46): a zsh prompt of 69 characters filled three rows at 23 columns and zsh wrote the input on the next line; after widening to 46 columns zsh moved up four rows, but the engine had measured the region from the first row of the cursor's logical line and left the cursor three rows below the prompt start, so the redraw overwrote the output row above the prompt. Done on 2026-10-02: the engine records the prompt start at `133;A` (and at ED 2 in the prompt state), keeps it correct when the scrollback drops rows, and clears from it for `redraw=1`; the bash integration sends `redraw=last`, which keeps the region of the cursor's logical line. A diagnostic build records the engine inputs of a surface (`SOKSAK_VT_TRACE_DIR`); the trace of the failing window check located the cause. Red: `a_widening_resize_counts_the_rows_of_a_prompt_that_ended_at_the_margin`, `a_resize_clears_every_row_from_the_prompt_start_when_the_prompt_ends_its_own_line` and `a_prompt_redrawn_after_a_screen_clear_starts_at_the_top_row` placed the cursor one to two rows too high; Green: they and `cargo test` pass, and the core zsh and bash redraw window checks pass twice on both hosts.
